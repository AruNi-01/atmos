# Brainstorm · APP-081: Mobile Agent Chat Web Parity

> Problem space, current-state audit, and open threads. Settled content graduates to PRD.md; committed architecture graduates to TECH.md.

## Context

APP-079 put Agent Chat on the phone: list → thread → composer, fed by the same `agent_chat_*` wire as web and folded with the same `@atmos/api-client/agent-chat` code. It deliberately stopped at "same information, same order, mobile chrome" (APP-079 PRD M7, TECH "Risks"). The transcript on the phone is therefore **recognizably the same conversation but not the same UI**: tool groups open a bottom sheet instead of expanding inline, there is no streaming reveal, no activity indicator, no scroll-to-bottom affordance, and the area above the composer shows at most a permission card and a session-op card.

Request (AruNi, 2026-10-15, relayed by Eng Manager): the phone Chat UI must use **the same UI as web** for message output and display, the conversation message list (every part: event / tool / thinking / error / session chrome), the cards above the input, and the input itself. Layout, presentation, effects, and animation should match web as closely as a native client can. Reference: web Agent Chat components under `apps/web/src/features/agent/`, the part tree and render rules in [QUALITY-006](../QUALITY-006_agent-event-identity/TECH.md), [QUALITY-008](../QUALITY-008_agent-chat-ui-optimization/TECH.md), [APP-067](../APP-067_atmos_agent_abs/TECH.md), [APP-068](../APP-068_agent_chat_arch_optimize/TECH.md), and the phone baseline in [APP-079](../APP-079_mobile-agent-chat/TECH.md).

Mobile-only exception: web stacks several cards above the input. The phone shows **at most one card at a time**; every card has a glass title pill in a horizontally scrollable row above the input, and tapping a pill expands that card (the scroll-to-bottom button joins that row, pinned left). Cards keep the phone's existing card look.

## Options

### Option A — Keep sheets; polish typography only

Cheap, but fails the request: tool/thinking display and animations stay different.

### Option B — Port the web rendering model to React Native (chosen direction)

Inline expandable process/tool tree, stream reveal, activity row, scroll affordances, composer card lane, all driven by the **same pure rules** as web. Native controls remain for the composer and sheets that are not part of the transcript.

**Pros**: Matches the request; parity can be tested at the rule level. **Cons**: Large UI port; some web effects (CSS `blur()` filter, mask-image, text shimmer) have no direct RN equivalent.

### Option C — WebView of the web transcript

Rejected in APP-079 (Fork 2/M8): auth, glass composer, native navigation. Still rejected.

## Forks to resolve

1. **New spec vs append to APP-079.** Resolved: new APP-081 (see PRD "Spec relationship"). APP-079 stays the functional baseline; APP-081 supersedes its transcript-display decisions (sheets, `Risks` bar).
2. **Shared pure logic.** (a) Extract web's pure modules (`tool-group`, `assistant-process-parts`, `agent-tree-branch` constants, `agent-chat-transcript-window` constants, `agent-chat-timing`, `agent-chat-below-count`) into `@atmos/agent-transcript` and import from both apps; web edits are import-path swaps only. (b) Keep mobile copies and add parity tests. Recommendation: (a) for parity-by-construction; it relaxes APP-079's "no `apps/web` changes" and needs approval.
3. **Web fixture surface** for same-session comparison: dev-only route in `apps/web` vs an out-of-tree harness under `scripts/` (like `scripts/agent-chat-stream-perf/`). Recommendation: out-of-tree harness; no production code path.
4. **Shimmer / blur / mask on RN**: which dependency, if any, is acceptable (`expo-linear-gradient` + `@react-native-masked-view/masked-view`, or Skia, or opacity pulse fallback). See TECH "Motion mapping".
5. **Card pill priority and auto-focus rule** when a permission request arrives while the user is reading another card. Proposed in PRD; confirm.
6. **"Glass card" meaning.** Mobile design rules (`agents/references/design/mobile.md`) say grouped content cards are plain `cardElevated` + hairline `glassBorder`, while _controls_ (buttons, chips) are `GlassPanel`. The existing above-composer cards (`AgentChatPermissionCard`, `AgentChatSessionOpCard`) follow that. This spec keeps that card style and uses `GlassPanel` only for the pill buttons. The reference screenshot ("图一") was described to this spec in words by AruNi via Eng Manager (horizontally scrollable row of glass pills above a rounded "Follow up…" input with `+` and microphone); the image file itself could not be read on the box, so pixel details (pill height, icon use, spacing) are marked "verify against the image" in TECH.
