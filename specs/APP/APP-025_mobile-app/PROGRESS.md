## Snapshot

- `apps/mobile` is scaffolded as a real Expo dev-client app with Expo Router, Expo UI wrappers, SecureStore token storage, TanStack Query, Zustand stores, NativeWind/react-native-css setup, and native iOS/Android project folders generated by Expo prebuild.
- Mobile connects to the Relay, imports a dev Access Token from local web settings in debug mode, auto-selects an online Computer, and loads the workspace list through the main app WebSocket.
- Workspace screens are terminal-first with one terminal renderer, a terminal picker/new-terminal model, fixed shortcut bar, and a mobile Changes & Commit tab.
- Changes & Commit uses existing Git WS actions for refresh, changed-file list, single-file inline diff, stage/unstage, commit, and push.
- Relay/API terminal stream code is implemented in the worktree, but the current production relay used for smoke checks still leaves mobile terminal streams disconnected.
- Do not port Web `TerminalGrid`, desktop Center Stage, Web right sidebar shell, editor open behavior, PR/notes/TODO/review panels, chunk patch controls, or AI commit generation into mobile M1.

### Task goal

Implement APP-025 mobile app as a real Expo native client using Expo UI where practical, simple Apple-style interactions, terminal-first workspace UX, and a minimal Changes & Commit workflow.

### Current progress

The app builds and launches as an Expo dev client on both iOS and Android. Workspace list, Computer selection, project/workspace routes, Changes, and single-file diff are smoke-tested. Terminal renderer mounts, but terminal transport through production relay is still disconnected.

- Mobile must render exactly one terminal at a time; multiple candidates require picker/switcher.
- No mobile-only REST shortcuts for project/workspace/Git business flows.
