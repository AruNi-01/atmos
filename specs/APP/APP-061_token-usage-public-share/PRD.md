# PRD · APP-061: Token Usage public share

> Product Requirements · WHAT and WHY. One vanity Token Usage page per Atmos user on `atmos.land`.

## Context

- **Problem**: Users can read Token Usage locally and export a PNG, but cannot give someone a **domain URL** that opens the same charts under their name.
- **Why now**: Atmos accounts (GitHub / Google via Hub) are live. The remaining gap is a public, branded page — not more identity work.
- **Related specs**:
  - [APP-056](../APP-056_usage-share-and-accounts/PRD.md) — Hub accounts, sessions, devices. This spec **replaces APP-056’s product share surface** (`/s/{share_id}`, auto handle, multi-share, landing HTML). Identity, devices, and Hub stay on APP-056.
  - [APP-050](../APP-050_shared-package-layering/PRD.md) — no speculative share package.

## Goals

1. Let a signed-in user publish **one** Token Usage page at `https://atmos.land/tok/@handle`.
2. Keep local Token Usage fully usable **without** an account.
3. Publish only **redacted aggregates** needed to render the existing charts (including top-N ranks).
4. Make the public charts **look like the in-app page**; wrap them with a thin profile shell (avatar, handle, socials, Atmos credit).

## Users & Scenarios

- **Primary persona**: Agentic builder who wants a link for X, GitHub, or a portfolio.
- **Secondary persona**: Friend or teammate opening an unlisted link with a secret.

### Key scenarios

1. Signed-in user opens local Token Usage → turns sharing on → claims `@handle` once → copies `https://atmos.land/tok/@handle` → visitor (logged out) sees the same charts plus the profile shell.
2. User chooses unlisted → copies a link that includes `@handle` and a secret → visitor without the secret sees a blocked/not-found state; with the secret they see the page.
3. Local usage grows → user clicks **Update** → the same URL shows the new snapshot and a new generated date.
4. User turns sharing off → the URL stops showing data.
5. Signed-out user still uses local Token Usage and PNG share; publish controls ask them to sign in.

```text
[Local Token Usage, no account]
  charts + PNG share
  publish → Sign in
       ↓
[Signed in] claim @handle (once) → public | unlisted → upload snapshot
       ↓ visitor
atmos.land/tok/@handle  (+ ?k= when unlisted)
       ↓ update
same URL, overwritten snapshot
       ↓ turn off
URL gone
```

## User Stories

- As a builder, I want a stable `atmos.land/tok/@me` link, so I can share usage without attaching a screenshot.
- As a builder, I want to pick my handle once, so the URL is mine and does not change under people who bookmarked it.
- As a builder, I want the public page to match the in-app charts, so visitors see the same story I see locally.
- As a builder, I want optional X and GitHub chips, so the page can point at me without a bio editor.
- As a privacy-conscious user, I want unlisted links and a way to turn the page off, so a pasted URL is not a permanent public profile.
- As a visitor, I want to know the page was generated by Atmos and when, so I do not treat it as live billing.

## Functional Requirements

### Must Have

- **M1 · Local-first**: Existing Token Usage (charts, year/metric/dimension toggles, cookie consent, PNG share) keeps working signed out and offline.
- **M2 · Sign-in to publish**: Publishing requires an Atmos account (Hub GitHub or Google). Publish UI lives on the local Token Usage page.
- **M3 · Claim-once handle**: User types the handle (placeholder `builder`). After a successful claim it is **immutable**. Length and charset limits apply. Duplicates are rejected. Reserved words are rejected.
- **M4 · One page per user**: At most one live snapshot. **Update** overwrites it. No share list, no second URL.
- **M5 · Visibility**:
  - **Off** — no public page.
  - **Public** — `https://atmos.land/tok/@handle` opens for anyone.
  - **Unlisted** — same path, plus a secret (`k`). Missing/wrong secret does not show data. Copy for humans: this is a capability link, not an ACL.
- **M6 · Manual refresh**: Snapshot is written only when the user turns sharing on or clicks Update. No background sync.
- **M7 · Slim snapshot**: Cloud stores only what the public charts need: all-time summary, per-day totals (heatmap / timeline / mix), **top 5** agent and model ranks plus an `other` residual, counts, `generated_at`. Cost fields only if the user includes cost. No prompts, paths, projects, raw sessions, or long-tail names.
- **M8 · Same charts**: Public body uses the **same** Token Usage overview UI as the app (tokens/cost, agent/model, year, heatmap, mix, stacked bars). Public page does **not** include cookie consent, local refresh, or PNG share.
- **M9 · Public shell**:
  - Top left: account avatar (OAuth image URL; letter fallback) + `@handle`. Avatar and handle are **not** links.
  - Top right: optional X and/or GitHub — icon + `@username`, only when the user saved a non-empty username. Links are `https://x.com/{user}` and `https://github.com/{user}`.
  - Bottom right: `Generated {date} · Generated by Atmos` (zh: date + `由 Atmos 生成`). **Atmos** links to `https://atmos.land` in a new tab.
- **M10 · Unpublish**: Turning sharing off makes the URL stop showing the snapshot immediately (no stale public cache).
- **M11 · Social usernames**: User enters **usernames only** (prefix shown in the form). Empty → not stored, not shown. Not auto-filled from the GitHub OAuth login.
- **M12 · Host**: User-visible URL is **`atmos.land`**, not `hub.atmos.land` or (as the primary copy) `app.atmos.land`.

### Nice to Have

- **N1 · Rotate unlisted secret** from the publish UI (old `k` dies).
- **N2 · Basic Open Graph title/description** on the public URL (no custom PNG required).
- **N3 · 301 alias** if we later allow handle change (explicitly **not** in v1).

## Out of Scope

- Multiple named shares or `/s/{share_id}` as the product URL (APP-056 share UX).
- Renaming a claimed handle.
- Continuous / multi-computer live sync.
- Uploading tokscale session files or transcripts.
- Password login or email-only accounts.
- Org / team pages.
- Leaderboards or year-in-review.
- Putting the public React page inside the Hub Worker.
- A new `packages/usage-share-view` / `packages/share`.
- Agent session (or other) share pages — later they may reuse the **shell + host**, not this chart view.
- Changing local PNG share behavior.
- Making the public page a logged-in-only view.

## Success Metrics

| Metric | Direction |
|--------|-----------|
| Publish completion | Signed-in user can produce a working `atmos.land/tok/@handle` from Token Usage |
| Local independence | Signed-out Token Usage still has full local charts + PNG |
| Privacy | Snapshot has no prompts/paths; unlisted without `k` shows no data; unpublish is immediate |
| Visual parity | Public body matches in-app overview charts for the published snapshot |
| Storage | Typical snapshot well under a small fixed cap (see TECH) |

## Risks & Open Questions

| Risk | Product mitigation |
|------|--------------------|
| Handle squatting / impersonation | Claim once; reserved words; unique; no rename |
| Unlisted link forwarded or scraped | Capability-link copy; rotate (N1); unpublish |
| Visitors think numbers are live billing | Footer generated date + Atmos credit |
| Cost accidentally public | Cost off unless the user includes it |
| Vanity URL is guessable | Public is explicit; unlisted requires `k` |

No open product forks remain from the design discussion. Cloudflare rewrite mechanics are TECH.

## Milestones

- **Phase 1**: M1–M12 — claim handle, publish/update/off, public + unlisted, slim snapshot, web view extract, atmos.land URL, shell.
- **Phase 2**: N1 rotate secret; N2 OG; later share types reuse the public host/shell only.
