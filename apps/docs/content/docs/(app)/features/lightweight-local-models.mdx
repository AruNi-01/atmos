---
title: AI Providers and Lightweight Local Models
description: Route helper tasks to cloud providers or small local models.
---

Atmos can use provider settings and routing rules for small helper tasks such as commit messages and workspace issue extraction. Lightweight local models let those jobs run on your own machine when you do not want every helper request to use a cloud model.

## Why it matters

- Extract task lists from workspace notes locally.
- Draft Git commit messages from the diff on device.
- Keep light inference off subscription quotas.
- Choose a different provider for lightweight helpers than the one you use for terminal coding agents.

## What you can configure

| Area | Use it for |
|------|------------|
| **Providers** | Add, enable, test, or disable model providers |
| **Routing** | Choose which provider handles Git commit generation and workspace issue TODO extraction |
| **Local models** | Download the local runtime, add models, start or stop inference, and delete models |
| **Custom GGUF** | Add a Hugging Face GGUF URL or local model file |

## Good local fits

- Short text generation and classification.
- Summaries of small inputs.
- Repetitive helpers that do not need frontier models.

## Not a replacement for

- Large refactors or multi-file reasoning.
- Tasks that need the latest frontier models—use your Code Agent CLI for those.

## Get started

1. Open **Settings** -> **AI & Provider**.
2. Add or test the provider you want to use.
3. Open routing settings and choose providers for commit messages or TODO extraction.
4. For local inference, download the local runtime and a small model.
5. Start the local model before using it for helper tasks.

## Tips

- Prefer quantized small models for speed on laptops.
- Verify GPU/CPU requirements before enabling on battery power.
- Keep terminal coding agents on the tools and models you already trust for large work.
