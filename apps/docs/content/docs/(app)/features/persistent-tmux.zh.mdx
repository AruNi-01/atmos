---
title: 持久终端会话
description: 让终端工作始终挂在对应工作空间上。
---

持久终端会话会把命令行工作挂在对应工作空间上。即使界面刷新、应用重启、连接断开，甚至电脑宕机重启，你也可以从同一个工作空间恢复终端，而不是从空白终端重新开始。

## 为什么重要

- 应用预览、测试运行和 Agent 会话在中断后可以恢复。
- Agent 执行的命令停留在稳定的 shell 上下文中。
- 关闭 Atmos 或重启电脑后也能快速恢复。
- 在一个工作空间中运行多个 shell，也不会丢失位置。

## 它如何工作

当你重新打开工作空间时，Atmos 会重新连接到已保存的终端会话，而不是从空白终端开始。

桌面和 Web 工作空间可以使用多个 pane 和 tab。需要恢复或清理 shell 状态时，**Terminal Manager** 可以帮助检查 system PTY、workspace terminal 和 orphaned session。

> 当前 Mobile App 处于开发阶段，暂时无法使用。

移动应用的终端界面更小：一次只渲染一个终端。它可以连接已有 session，也可以创建新的移动端终端，但断线时不会排队发送终端输入。

## 终端 AI 命令

在终端 AI Input（`/` 菜单）中：

| 命令 | 用途 |
|------|------|
| **`/side`** | 从当前面板分叉临时 side chat — [终端 Side Chat](/zh/features/terminal-side-chat) |
| **`/spawn`** | 复用当前 Agent 上下文的新终端面板 |
| **Dynamic Skills** | 临时隐藏本上下文中 Agent 可见的 Skills |

关闭仍有运行中面板的终端标签页时会先确认，避免误杀进行中的工作。

## 开始使用

1. 打开一个工作空间。
2. 打开 **Terminal** 面板。
3. 运行你常用的开发、测试或 Agent 命令。
4. 切到编辑器、Canvas 或另一个工作空间；回来时仍然是同一个会话。

## 使用建议

- 如果同时打开多个终端，给会话起名字。
- 如果输出看起来卡住了，在那个面板里停止进程，然后从同一个工作空间重新运行。
- 当 Agent 在多个分支上并行工作时，和 [多工作空间开发](/zh/features/multi-workspace) 搭配使用。
- 使用终端设置选择文件链接的打开方式，以及默认 split prompt 使用哪个 Agent。
