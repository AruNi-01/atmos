---
title: AI Provider 与轻量本地模型
description: 把辅助任务路由到云端 Provider 或小型本地模型。
---

Atmos 可以用 Provider 设置和路由规则处理提交信息、workspace issue 提取等小型辅助任务。轻量本地模型让这些任务在你的机器上运行，而不是把每个辅助请求都发给云端模型。

## 为什么重要

- 在本地从工作空间笔记中提取任务列表。
- 根据 diff 在设备上起草 Git 提交信息。
- 让轻量推理避开订阅额度。
- 为轻量辅助任务选择和终端编码 Agent 不同的 Provider。

## 可以配置什么

| 区域 | 用途 |
|------|------|
| **Providers** | 添加、启用、测试或停用模型 Provider |
| **Routing** | 选择由哪个 Provider 处理 Git commit 生成和 workspace issue TODO 提取 |
| **Local models** | 下载本地 runtime、添加模型、启动或停止推理、删除模型 |
| **Custom GGUF** | 添加 Hugging Face GGUF URL 或本地模型文件 |

## 适合本地处理什么

- 短文本生成和分类。
- 小输入的摘要。
- 不需要前沿模型的重复性辅助任务。

## 不能替代什么

- 大型重构或多文件推理。
- 需要最新前沿模型的任务；这些任务请使用你的 Code Agent CLI。

## 开始使用

1. 打开 **Settings** -> **AI & Provider**。
2. 添加或测试你要使用的 Provider。
3. 打开 routing 设置，为提交信息或 TODO 提取选择 Provider。
4. 如果要本地推理，下载本地 runtime 和小模型。
5. 在使用辅助任务前启动本地模型。

## 使用建议

- 在笔记本上优先选择量化小模型，速度更快。
- 用电池供电前，先确认 GPU/CPU 要求。
- 大型编码任务仍然交给你已经信任的终端 Agent 和模型。
