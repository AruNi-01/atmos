Skills are reusable instructions for agents. They can capture review checklists, writing standards, project habits, or repeatable workflows so you do not have to explain the same thing every time.

## Why it matters

- Stop retyping the same agent instructions.
- Keep behavior consistent across teammates.
- Turn specialized workflows on only when they help the task.
- Remove skills that are outdated or too broad.

## What you can do

- Browse available skills in the app.
- Enable or disable skills with one click.
- Delete skills you no longer use.
- Combine skills with [Agent Chat Panel](/features/agent-chat-panel) for focused tasks.
- Use skills from chat, review, automation, and terminal-agent workflows when the surface supports them.

Skills are different from agent definitions. Use **Settings** -> **Code Agent** for built-in terminal agents, custom agent commands, and saved run configurations.

## Get started

1. Open **Skills** in Atmos.
2. Review descriptions to understand each skill’s job.
3. Enable skills that match your current project.
4. Disable or remove skills that add noise.

## Dynamic Skills (composer & terminal)

Need to mute a skill without leaving Welcome or the terminal AI Input? Type `/` and open **Dynamic Skills**.

It uses the same enable/disable files as this page. Project toggles stay in sync here; workspace toggles apply only under the current workplace (important when sync dirs use symlink or copy).

See [Dynamic Skills](/how-it-works/dynamic-skills) for the full walkthrough—scope, on-disk layout, and how workspace symlink sync is kept workplace-local.

## Tips

- One skill, one job—split oversized skills into smaller ones.
- Revisit skills when you change team process or tooling.
- Keep skills specific enough that an automation or review agent can apply them without extra explanation.
