# Atmos Main 每日代码质量评分

在当前工作区仓库中，只审查 `main` 分支前一天产生的所有提交。时间范围以 UTC+8（Asia/Shanghai）自然日为准，即昨天 `00:00:00` 到 `23:59:59`。

报告语言：中文。

## 核心边界

- 这是代码质量与设计质量 review，不是功能验收，也不是产品/需求 review。
- 只看本次提交引入、放大或改善的质量问题，不把历史债务直接算到当天提交头上。
- 结果不得包含本机绝对路径、token、secret 或完整环境变量。
- 文件路径使用仓库内路径，例如 `apps/...`、`crates/...`、`automations/review/quality/result/YYYY-MM/...`。

## 按需加载

按下面顺序加载额外指令，不要一次性加载无关场景：

1. 开始筛选提交前，读取 `references/scope-and-commit-selection.md`。
2. 如果筛选后存在可审查的业务/代码提交，读取 `references/scoring-rubric.md`，再开始 review 和评分。
3. 写任何报告、结果文件或结果提交前，读取 `references/report-and-result.md`。
4. 如果总分低于 90，读取 `references/auto-fix-pr.md`，然后再修改代码、创建分支、提交或开 PR。

## 执行流程

1. 同步并确认 `main` 最新状态。
2. 根据 UTC+8 昨日自然日窗口筛选 `main` 提交，并排除 automation 结果归档提交。
3. 如果没有可审查业务/代码提交，按无提交场景写报告、落盘、提交并推送结果；不要修复，不要创建 PR。
4. 如果有可审查提交，先看 diff，再看必要上下文，按评分规则输出中文质量报告。
5. 总分大于等于 90 时，只提交并推送结果文件。
6. 总分低于 90 时，自动进入修复流程，尽最大可能交付可 review 的修复 PR。

## 不确定时

- 证据不足只能写“推测”，不能当成事实。
- 不要凑问题数量；当天质量很好就明确写“未发现明确质量问题”。
- 如果工作树存在 automation 之外的未提交改动，不要覆盖或回滚；按场景指令处理阻塞。
